01痛点与直觉：从单头玩具走向真正 GPT 的两道关卡

第 1 课的单头自注意力已经能让任意两个词一步直连，但要把它装进 GPT / LLaMA / Qwen 这样的现代大语言模型，立刻会撞上两个致命问题：

Encoder vs Decoder：BERT 这类双向理解模型做完形填空，不需要因果掩码（双向全可见）；而所有生成式大模型（GPT、LLaMA、Qwen、MiniMind）全都是 Decoder-only 自回归架构，因果掩码是它们的生命线。
关卡一：并行训练时的「未来答案偷看」灾难（Causal Mask）

大语言模型的预训练目标是 Next-Token Prediction（预测下一个词）。为了榨干 GPU 算力，训练时我们不会一个词一个词串行喂，而是把整句 ["我", "爱", "深", "度"] 一次性并行送进网络，同时让位置 0 预测「爱」、位置 1 预测「深」、位置 2 预测「度」。
如果不加限制，第 0 个词「我」的 Query 在算 $QK^\top$ 时就能直接看到右边第 1 个词「爱」的 Key 和 Value！模型根本不用学语言规律，直接把右邻居抄过来就能让训练 Loss 秒降为 $0$；可一旦上考场做真实推理（右边还没有生成出来！），模型瞬间变成睁眼瞎胡言乱语。

关卡二：单组 Softmax 的「赢家通吃」瓶颈（Multi-Head Attention）

在单头注意力里，每个词只有唯一一组和为 $1.0$ 的概率分布。指数函数具有强烈的「赢家通吃」特性——比如代词「它」可能把 $85\%$ 的权重都花在了找指代对象上，就再也腾不出注意力去同时盯住「谓语动词时态」和「相邻介词搭配」。
多头注意力（MHA）的妙招：不增加总维度，直接把长 $C$ 的特征向量均切成 $H$ 份独立低维子空间（每头维度 $d_k = C / H$），让 $H$ 个头各自拥有一套独立的 Softmax 账本并行打分——头 1 盯主谓语法、头 2 盯指代消解、头 3 盯局部词组，最后拼接过一层 $W_O$ 汇总，表达能力翻倍，总参数量和总计算量却与单头 $C$ 维分毫不差！

02因果掩码铁律：为什么必须填 $-\infty$ 且在 Softmax 之前？

初学者手撕因果注意力时，最容易写出的一个致命 Bug 是：「先算完正常的 $\text{Softmax}(QK^\top / \sqrt{d_k})$，再乘一个下三角全 1、上三角全 0 的掩码矩阵把未来权重抹成 0」。这在数学和梯度上都是大错特错的！

我们直接拿 $T=4$ 句子 ["我", "爱", "深", "度"] 的缩放后分数矩阵 $S \in \mathbb{R}^{4\times 4}$ 来算一笔硬账（行 $i$ 为当前提问位置，列 $j$ 为被看位置，$j > i$ 的右上三角即为「未来」）：

$$S = \begin{pmatrix} 1.0 & \color{#c2410c}{2.0} & \color{#c2410c}{0.5} & \color{#c2410c}{-0.5} \\ 0.8 & 1.2 & \color{#c2410c}{2.4} & \color{#c2410c}{0.2} \\ 0.4 & 1.0 & 1.5 & \color{#c2410c}{2.2} \\ 0.6 & 0.9 & 1.4 & 1.8 \end{pmatrix}$$

构造上三角掩码矩阵 $M_{ij} = 0\ (i \ge j),\ M_{ij} = -\infty\ (i < j)$，相加得 $S + M$，再按行做 Softmax。因为 $\exp(-\infty) = 0$，每一行的归一化分母只累加合法历史 $j \le i$：

  • 第 0 行（「我」，只能看自己）：输入 $[1.0, -\infty, -\infty, -\infty] \implies \frac{e^{1.0}}{e^{1.0} + 0 + 0 + 0} = [\mathbf{1.0000},\ 0,\ 0,\ 0]$（行和 $= 1.0$）。
  • 第 1 行（「爱」，可看「我、爱」）：输入 $[0.8, 1.2, -\infty, -\infty] \implies \frac{[e^{0.8}, e^{1.2}]}{e^{0.8}+e^{1.2}} \approx [\mathbf{0.4013},\ \mathbf{0.5987},\ 0,\ 0]$（行和 $= 1.0$）。

若先对未遮挡的第 0 行 $[1.0, 2.0, 0.5, -0.5]$ 做 Softmax：

$$A_{\text{full}}[0] = \frac{[e^{1.0},\ e^{2.0},\ e^{0.5},\ e^{-0.5}]}{2.7183 + \color{#c2410c}{7.3891 + 1.6487 + 0.6065}} \approx [0.2199,\ \color{#c2410c}{0.5977,\ 0.1334,\ 0.0491}]$$

事后再乘 $[1, 0, 0, 0]$ 抹零，得到 $A_{\text{post}}[0] = [\mathbf{0.2199},\ 0,\ 0,\ 0]$！灾难发生了两重：
① 概率分布崩塌：第 0 行权重之和只剩 $0.2199$（丢掉了 $78\%$ 的特征幅值！第 1 行也只剩 $0.3117$）；
② 未来信息经由分母幽灵穿越 + 反向梯度污染：为什么唯一合法的 $A_{\text{post}}[0,0]$ 会等于 $0.2199$？因为分母里加了未来词「爱」的 $e^{s_{01}} = e^{2.0}$！如果未来换一个词使 $s_{01}$ 变大，$A_{\text{post}}[0,0]$ 就会跟着变小——模型照样能通过这个缩放比例反推出未来是什么词！用 PyTorch 求导更能实锤：此时未来分数竟有非零梯度 $\frac{\partial A_{\text{post}}[0,0]}{\partial s_{01}} = -A_{\text{full}}[0,0]A_{\text{full}}[0,1] = \mathbf{-0.1314} \neq 0$！

很多老教程喜欢写 scores.masked_fill(mask, -1e9)。这在 FP32 和 BF16（8 位指数，上限 $\sim 3.4\times 10^{38}$）下没问题，但一旦放到 FP16（如 Colab T4 开启 fp16=True，5 位指数最大只能表示 $\pm 65504$），直接抛异常：RuntimeError: value cannot be converted to type at::Half without overflow！

工业级标准写法永远只有两种：直接填 IEEE 负无穷 float("-inf")，或自适应类型极小值 torch.finfo(scores.dtype).min。

(因果自注意力公式)

$$\text{CausalAttention}(Q, K, V) = \text{Softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V, \qquad M_{ij} = \begin{cases} 0, & j \le i \\ -\infty, & j > i \end{cases}$$

$i, j \in \{0, \dots, T-1\}$
行号 $i$ 为当前生成步 Query 位置，列号 $j$ 为历史/未来 Key 位置
$j > i$（严格上三角）
对应 `torch.triu(..., diagonal=1)`（注意对角线 $j=i$ 必须保留为 $0$，否则第 0 行全为 $-\infty$ 会算出 $0/0 = \text{NaN}$！）

03多头注意力（MHA）全链路 Shape 变形记

手撕 MHA 时，90% 的同学不是挂在注意力公式，而是挂在 view 和 transpose 的维度顺序上。记住我们的配置约定：总隐藏维 $C = H \times d_k$（例如 $C = 512,\ H = 8 \implies d_k = 64$）。

阶段与 PyTorch 操作张量 Shape设计意图与手撕必考追问
0. 输入序列 x(B, T, C)批次 $B$，序列长 $T$，通道维 $C = d_{\text{model}}$
1. 三路整块投影 wq(x), wk(x), wv(x)(B, T, C)不用写 $H$ 个小 Linear 循环！直接用大矩阵 $(C, C)$ 一次算出所有头的拼接态
2. 切分子空间 .view(B, T, H, d_k)(B, T, H, d_k)零拷贝重解释最后一维 $C \to (H, d_k)$，词序 $T$ 仍在第 1 维
3. 轴交换 .transpose(1, 2)(B, H, T, d_k)灵魂一步！把 $(B, H)$ 放到前两维当联合 Batch，最后两维留给 $(T, d_k)$
4. 并行打分 q @ k.transpose(-2, -1)(B, H, T, T)GPU 一次性并行算出 $B \times H$ 张独立的 $T \times T$ 注意力矩阵！
5. 加权聚合 attn @ v(B, H, T, d_k)每个头在各自 $d_k$ 子空间内独立聚合完 Value
6. 拼回多头 .transpose(1, 2).contiguous().view(B, T, C)(B, T, C)先把轴换回 (B, T, H, d_k)，重排连续内存后展平回 $C$ 维
7. 跨头融合 wo(merged)(B, T, C)右乘 $W_O \in \mathbb{R}^{C \times C}$，让 $H$ 个头提取的不同关系充分交叉混合
手撕面试官最爱追问的两个细节（务必脱口而出！）

追问 A：第 3 步如果不做 transpose(1, 2) 直接矩阵乘会发生什么？
PyTorch 的 @ 只在最后两维做矩阵乘，前面所有维度按 Batch 对齐。如果不交换，张量是 (B, T, H, d_k)，执行 q @ k.transpose(-2, -1) 会变成对每个词位置算 (H, d_k) @ (d_k, H) → (H, H)（头与头算内积！），彻底背离词与词交互 (T, T) 的物理意义！

追问 B：第 6 步为什么 transpose(1, 2) 后面必须紧跟 .contiguous() 才能调 .view()？
transpose 为了省时间只修改了张量头部的步长元数据（stride），物理显存里的元素依然按 (B, H, T, d_k) 排列（内存不连续）。而 .view(B, T, C) 要求底层物理地址严格连续才能零拷贝合并最后两维，否则直接抛 RuntimeError: view size is not compatible with input tensor's size and stride！加上 .contiguous()（或直接用自动按需拷贝的 .reshape(B, T, C)）即可安全过关。

04代码讲解：PyTorch 黄金 14 行手撕模板与因果掩码

左侧截取自 11-Attention与Transformer从零实现.ipynb · Cell#9 的标准 PyTorch 多头实现（已与官方 nn.MultiheadAttention 逐位对齐误差 $< 10^{-7}$）：

class MHA_manual(nn.Module):
    def __init__(self, d, heads):
        super().__init__()
        self.d, self.h = d, heads
        self.dh = d // heads
        self.wq = nn.Linear(d, d); self.wk = nn.Linear(d, d)
        self.wv = nn.Linear(d, d); self.out = nn.Linear(d, d)
    def forward(self, x):
        B, T, _ = x.shape
        q = self.wq(x).view(B, T, self.h, self.dh).transpose(1, 2)
        k = self.wk(x).view(B, T, self.h, self.dh).transpose(1, 2)
        v = self.wv(x).view(B, T, self.h, self.dh).transpose(1, 2)
        a = torch.softmax(q @ k.transpose(-2, -1) / (self.dh ** 0.5), dim=-1) @ v
        return self.out(a.transpose(1, 2).reshape(B, T, self.d))
  1. 四块 $(d, d)$ 权重矩阵：d 必须整除 heads，单头维 dh = d // heads；wq, wk, wv, out 共 $4d^2$ 参数（現代 LLM 常设 bias=False）。
  2. 投影 + 切头 + 换轴三连：(B, T, d) → (B, T, h, dh) → (B, h, T, dh)，一步让所有头进入并行轨道。
  3. 单头维度缩放：注意这里除以的是单头维度 $\sqrt{d_h} = \sqrt{d / h}$，而不是总维度 $\sqrt{d}$！因为每个内积只累加了 $d_h$ 项。
  4. 归位拼接 + $W_O$ 跨头融合：.reshape(B, T, self.d) 等价于 .contiguous().view(B, T, self.d)；最后经 self.out 完成多子空间信息交互。

三种必会因果掩码代码对照（训练全量 vs 推理 KV Cache）

# ---------- 实验 3：因果掩码（Decoder 只看左侧） ----------
# 掩码放入 softmax 前：下三角保留，上三角填 -inf → softmax 后为 0
def causal_mask(T):
    return torch.triu(torch.full((T, T), float('-inf')), diagonal=1)

T = 5
def causal_mask(nq, nk):
    """因果掩码：query 全局位置 = nk-nq+i，屏蔽 j > 自己全局位置（未来 key）。
    全量时 nq=nk=8 退化为上三角；增量 decode 时 nk=缓存长度 > nq。"""
    i = np.arange(nq)[:, None]; j = np.arange(nk)[None, :]
    return (nk - nq + i) < j
    B, T, d_model = x.shape

    # ========== 步骤①：QKV线性投影 ==========
    # 输入x[B,T,d_model] 乘权重 + 偏置，得到完整维度的Q、K、V，shape均为 [B, T, d_model]
    Q = x @ W_q + b_q
    K = x @ W_k + b_k
    V = x @ W_v + b_v

    # ========== 步骤②：拆分多头 reshape + transpose ==========
    # reshape(B, T, h, d_k): 在特征维度d_model拆成 h个头 × 单头维度d_k；T（token数量）不变，所有头看到全部token
    # transpose(0, 2, 1, 3): 调换维度顺序：[B,T,h,dk] → [B,h,T,dk]
    # 维度含义 [batch, head, token, feature]，把头放到第二维，方便循环遍历每一个头
    Q = Q.reshape(B, T, h, d_k).transpose(0, 2, 1, 3)
    K = K.reshape(B, T, h, d_k).transpose(0, 2, 1, 3)
    V = V.reshape(B, T, h, d_k).transpose(0, 2, 1, 3)

    # ========== 步骤③：逐个头，独立运行缩放点积注意力 ==========
    attn_all = np.zeros((B, h, T, T))   # 存放每一个头的注意力权重矩阵
    heads = []                          # 存放每个头的输出，每个元素shape [B,T,d_k]
    for i in range(h):
        # Q[:,i]取出第i个头的Q/K/V，shape [B,T,d_k]
        out_i, attn_i = scaled_dot_attention(Q[:, i], K[:, i], V[:, i], mask)
        heads.append(out_i)
        attn_all[:, i] = attn_i

    # ========== 步骤④：拼接所有头输出 ==========
    # 沿最后一维（特征维度）拼接h个头输出
    # concat shape: [B, T, h*d_k] = [B, T, d_model]，恢复原始模型隐层维度
    concat = np.concatenate(heads, axis=-1)
    
    # ========== 步骤⑤：输出线性投影 W_o ==========
    out = concat @ W_o + b_o  # [B,T,d_model]

06小结与面试表达模板

本课核心四条
  • 因果掩码铁律：必须在 Softmax 之前将上三角 $j > i$ 置为 $-\infty$（工程用 float("-inf") 或 torch.finfo(dtype).min），使 $\exp(-\infty)=0$ 且分母仅对合法历史归一化。
  • 事后置零两大罪状：一破坏每行概率和为 $1$ 的凸组合性质；二让未来分数混入 Softmax 分母，前向泄露信息、反向对未来 Token 产生非零梯度 $-p_{ii}p_{ij}$。
  • 多头零额外开销：将 $C$ 维切为 $H$ 个 $d_k = C/H$ 子空间，四块投影矩阵总参数量仍为 $4C^2$，注意力核心计算量仍为 $O(B T^2 C)$。
  • 手撕重排口诀：view(B,T,H,d_k).transpose(1,2) 借轴并行 → 除 $\sqrt{d_k}$ 算因果注意力 → transpose(1,2).contiguous().view(B,T,C) 归位 → 乘 Wo 跨头融合。
30 秒面试高分回答模板

「GPT 类自回归模型训练时整句并行输入，因果掩码在 Softmax 前把上三角 $j>i$ 加上 $-\infty$，保证 $\exp(-\infty)=0$，既屏蔽未来权重又确保历史位置概率和严格为 1；如果先 Softmax 再乘 0/1 掩码，未来词已经参与了分母求和，会导致特征幅值缩水且反向传播向未来词泄露梯度。多头注意力则把 $C$ 维切成 $H$ 个 $d_k=C/H$ 的低维子空间，通过 transpose(1, 2) 把头维提到前面批量并行，让不同头同时捕捉语法、指代和局部搭配等多种关系，最后拼接经 $W_O$ 融合，总参数量依然保持 $4C^2$ 不变。」

07想检验一下？（可选 · 点击展开）

1. 🎤 面试追问：多头注意力有 $H$ 个头，为什么总参数量是 $4C^2$ 而不是 $4 H C^2$？（以 $C=512,\ H=8$ 算具体数字）

每个头的投影矩阵并不是从 $C$ 投到 $C$，而是从 $C$ 投到单头低维 $d_k = C / H$！即单头的 $W_i^Q \in \mathbb{R}^{C \times (C/H)}$ 参数量是 $C^2 / H$。把 $H$ 个头的 $W_1^Q, \dots, W_H^Q$ 横向拼在一起，恰好合成一整块 $W_Q \in \mathbb{R}^{C \times C}$，参数量为 $H \times \frac{C^2}{H} = C^2$。加上同样大小的 $W_K, W_V$ 以及最后的融合矩阵 $W_O \in \mathbb{R}^{C \times C}$（不计偏置），总参数量恒为 $4C^2$。
代入 $C = 512,\ H = 8$：$d_k = 64$，总参数量 $= 4 \times 512^2 = \mathbf{1,048,576}$（约 $1.05\text{M}$），与 $H$ 取 $1, 8, 16$ 完全无关！

2. 🎤 面试追问：在 Colab T4 上开启 fp16=True 训练时，写 scores.masked_fill(mask, -1e9) 为什么直接报错崩溃？叠加 Padding Mask 时又为什么会冒出 NaN？

两个经典线上事故：
① FP16 溢出崩溃：IEEE 754 半精度浮点数（FP16）只有 5 位指数位，可表示的最大有限范围是 $\pm 65504$，-1e9 远超范围直接触发 RuntimeError: value cannot be converted to type at::Half without overflow。应改用 float("-inf")、-1e4 或 torch.finfo(scores.dtype).min（在 PyTorch 2.x 中更推荐直接调 F.scaled_dot_product_attention(..., is_causal=True)）。
② 全行 $-\infty$ 导致 0/0 = NaN：当左填充（Left Padding）或某些样本整行 Key 全被 Padding + Causal Mask 置为 $-\infty$ 时，行最大值 $m = -\infty$，x - m 变成 (-inf) - (-inf) = NaN（或分子分母全 0 得 0/0 = NaN）！因此对纯 Padding 废词位置，要么保证至少对角线自身可见，要么在 Loss 处用 ignore_index=-100 屏蔽。

3. 🎤 面试追问：开启 KV Cache 做自回归逐词生成（Decode 阶段）时，每次输入的 Query 长度 $T_q = 1$、缓存 Key 长度 $T_k = 100$，这时还需要加因果掩码吗？

单条无 Padding 序列在 Decode 阶段完全不需要加因果掩码！
原因很简单：Prefill（预填充提示词）阶段 $T_q = T_k$，前面的词不能看后面的词，必须加 $T_q \times T_q$ 上三角掩码；而进入逐词 Decode 阶段后，当前送进去的唯一 1 个 Query 就是全场最新的第 $100$ 号位置，KV Cache 里存的 $0 \sim 99$ 号位置 + 当前第 $100$ 号位置全部都是它的合法过去与自身（对应 §4 Tab ② 公式 (nk - nq + i) < j 中 nq=1, i=0，条件 nk - 1 < j 对所有 $j \in [0, nk-1]$ 恒为 False）！省掉掩码还能让底层直接跑更轻量的矩阵向量乘（GEMV）解码内核。
