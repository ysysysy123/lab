01痛点与直觉：现代开源 LLM 对 2017 原版架构的最后两刀改造

前两节课我们已经把 2017 原版 Transformer 的位置编码换成了 RoPE，把残差归一化换成了 Pre-Norm + RMSNorm。要拼齐今天 LLaMA、Qwen、DeepSeek、MiniMind 的现代标准底座，还剩最后两块最吃参数与显存的核心积木：

  • 第一刀砍向 FFN（占整模约 $2/3$ 参数量的「静态知识记忆库」）：原版单路 $\text{ReLU}(xW_1)W_2$ 遇到负数一刀切零（Dead ReLU 神经元永久坏死），且只是简单的线性投射加截断；现代 LLM 全员换装带软门控的 SwiGLU，用双路逐元素相乘动态控制每个特征通道的开合度，同参数预算下困惑度（PPL）显著下降。
  • 第二刀砍向推理头号瓶颈 Attention KV Cache：自回归生成时，每吐出 1 个新词都要读取所有历史 Token 的 $K, V$ 向量。当上下文拉到 $32\text{K}$ 时，原版 MHA 的 KV Cache 高达 $16\text{ GiB}$——比 7B 模型权重本身（$14\text{ GiB}$）还肥，直接把你的 RTX 4080（12GB）撑到 OOM！现代模型改用 GQA（Grouped-Query Attention） 让一组 Query 头共享同一份 KV 头，KV 显存立砍 4–8 倍而精度几乎零损失！
一句话抓住两项改造的灵魂

SwiGLU 给前馈网络装上了「可学习的无级调光旋钮」（一路产内容、一路拧阀门）；
GQA 把「每人独享一套参考书（MHA）」改成了「4–7 人学习小组共用一套参考书（KV Cache）」，书架空间立省 80%，做题准确率却几乎一样高！

02SwiGLU 门控前馈网络与 $\frac{8}{3}d$ 参数对齐推导

从单路 ReLU 到双路门控 SwiGLU

SwiGLU（Shazeer, 2020）由 Swish / SiLU 激活函数与 GLU（门控线性单元）结合而成。先看激活函数 $\text{SiLU}(z) = z \cdot \sigma(z) = \frac{z}{1 + e^{-z}}$：它在正半轴近似恒等，在负半轴（约 $z \approx -1.28$ 处有极小负谷底 $-0.278$）平滑趋于 $0$，处处可导且无死区。

SwiGLU

$$\text{SwiGLU}(x) = \Big(\underbrace{\text{SiLU}(x W_{\text{gate}})}_{\text{软门控阀门}} \;\odot\; \underbrace{(x W_{\text{up}})}_{\text{候选内容}}\Big) W_{\text{down}}$$

$W_{\text{gate}}, W_{\text{up}} \in \mathbb{R}^{d \times d_{ff}}$
两个并行的升维无偏置线性层，分别把每个 Token 从隐藏维 $d$ 投射到中间维 $d_{ff}$
$\odot$（Hadamard 积）
逐通道相乘：相当于在特征空间引入二阶双线性交互，门控值决定放行、反转还是抑制对应通道内容
$W_{\text{down}} \in \mathbb{R}^{d_{ff} \times d}$
降维投影层，把门控筛选后的高维特征压回主干维度 $d$ 汇入残差流

极小具体数字手算：$d=2,\ d_{ff}=3$ 看门控如何拧水龙头

取单 Token 输入 $x = [1.0,\ 2.0]$，设三块无偏置权重矩阵（经 verify_0005.py 与 PyTorch F.silu 严格核对）：

$$W_{\text{gate}} = \begin{bmatrix} 1.0 & -1.0 & 0.0 \\ 0.5 & 0.0 & -2.0 \end{bmatrix}, \quad W_{\text{up}} = \begin{bmatrix} 0.5 & 1.0 & 1.0 \\ 0.5 & 1.5 & 1.0 \end{bmatrix}, \quad W_{\text{down}} = \begin{bmatrix} 1.0 & 0.0 \\ 0.5 & -1.0 \\ 0.0 & 2.0 \end{bmatrix}$$

  1. 算门控支路并过 SiLU：$g = x W_{\text{gate}} = [2.0,\ -1.0,\ -4.0]$，逐元素算 $z \cdot \sigma(z)$： $$\text{SiLU}(g) = \big[2\sigma(2),\ -1\sigma(-1),\ -4\sigma(-4)\big] \approx \mathbf{[1.761594,\ -0.268941,\ -0.071945]}$$
  2. 算内容支路：$u = x W_{\text{up}} = \mathbf{[1.5,\ 4.0,\ 3.0]}$。
  3. 逐元素相乘（3 个通道呈现 3 种鲜明状态！）： $$h = \text{SiLU}(g) \odot u \approx \big[\underbrace{2.642391}_{\text{通道 0：正向放大放行}},\; \underbrace{-1.075766}_{\text{通道 1：平滑负向调制}},\; \underbrace{-0.215835}_{\text{通道 2：阀门关小强力抑制}}\big]$$
  4. 降维投回主干：$y = h W_{\text{down}} \approx \mathbf{[2.104508,\ 0.644097]}$。
面试必考口算推导：为什么 Llama-2-7B 的 intermediate_size 偏偏是 11008，而不是传统的 $4d = 16384$？

第一步（等参数量 / 等 FLOPs 对齐）：

  • 传统 2 矩阵 FFN（$W_1 \in \mathbb{R}^{d\times 4d},\ W_2 \in \mathbb{R}^{4d\times d}$）总参数量为：$2 \times d \times 4d = \mathbf{8d^2}$；
  • SwiGLU 有 3 个矩阵（$W_{\text{gate}}, W_{\text{up}}, W_{\text{down}}$），总参数量为：$\mathbf{3 d d_{ff}}$；
  • 为保持总参数量与计算量不变，令 $3 d d_{ff} = 8 d^2 \implies \mathbf{d_{ff} = \frac{8}{3}d \approx 2.667\,d}$！

第二步（GPU Tensor Core 硬件块对齐）：在 Llama-2-7B 中隐藏维 $d = 4096$，理论值 $\frac{8}{3} \times 4096 = 10922.67$ 除不尽。为了喂饱 GPU Tensor Core 矩阵乘分块（multiple_of = 256），向上取整到 $256$ 的最小整数倍：

$$d_{ff} = \left\lceil \frac{10922.67}{256} \right\rceil \times 256 = 43 \times 256 = \mathbf{11008}$$

核对账本：此时单层 SwiGLU 参数量 $3 \times 4096 \times 11008 \approx 135.27\text{M}$，与传统 $8d^2 \approx 134.22\text{M}$ 相差不到 $0.78\%$！

03GQA 分组查询注意力与 KV Cache 字节级显存账本

为什么推理必须开 KV Cache？（Prefill vs Decode）

大模型自回归生成一句话分为两个截然不同的阶段：

  • Prefill（预填充）：一次性并行读入用户的整段 Prompt（长度 $T_0$），算出所有历史位置的 $K_{1:T_0}, V_{1:T_0}$ 存进显存（KV Cache），并吐出第 1 个新词（计算密集 Compute-Bound）。
  • Decode（逐词解码）：生成第 $t$ 个词时，由于因果掩码限制，前 $t-1$ 个词的 $K, V$ 早已固定不变！模型每次只喂入最新 1 个词 (B, 1, d)，算出 $q_t, k_t, v_t$，把 $k_t, v_t$ 拼到缓存末尾，拿 $q_t$ 与整条历史缓存做点积——单步计算复杂度从重算全句的 $O(t^2)$ 骤降到 $O(t)$，但每吐 1 个词都必须把庞大的 KV Cache 从 HBM 搬进核心一遍（典型的显存带宽受限 Memory-Bound）！

MHA → MQA → GQA：点击切换三种头分组映射拓扑

下面以 8 个 Query 头直观演示三种注意力变体的头共享方式（工业 7B 模型通常 $H_q=32, d_k=128$）：

$H_{kv} = H_q = 32$（每组 $g = 1$）：每个 Query 头各自配一套专属的 Key / Value 头。表达能力上限最高，但 Decode 阶段每生成一个词都要搬运全部 32 组历史 KV，长上下文下显存与带宽双双告急。

$H_{kv} = 1$（组大小 $g = H_q = 32$）：所有 32 个 Query 头全部指向唯独 1 组公共的 Key / Value 头！KV Cache 瞬间缩小 32 倍，但过度压缩键值空间会导致复杂推理与长文检索质量下滑。

$1 < H_{kv} < H_q$：把 $H_q$ 个 Query 头均分成 $H_{kv}$ 组，每组 $g = H_q / H_{kv}$ 个 Q 头共享 1 份 KV 头！
• Llama-3-8B：$H_q = 32,\ H_{kv} = 8 \implies g = 4$（KV 显存直砍 $4\times$）；
• Qwen2.5-7B：$H_q = 28,\ H_{kv} = 4 \implies g = 7$（KV 显存直砍 $7\times$）；
• MiniMind：$H_q = 8,\ H_{kv} = 4 \implies g = 2$（KV 显存直砍 $2\times$）。

Decode 单步阶段张量Shape（以 $T_{\text{cur}}=1$ 为例）物理含义与防坑要点
x_cur(B, 1, d)当前步刚喂入的 1 个最新 Token 隐藏状态
q(B, H_q, 1, d_k)完整拆出 $H_q$ 个查询头，随后施加当前位置 pos 的 RoPE 旋转
k_new, v_new(B, H_kv, 1, d_k)仅投影出 $H_{kv}$ 个头！对 k_new 施加 RoPE（v_new 不转）
k_cache, v_cache(B, H_kv, T_all, d_k)沿序列维 axis=2 拼接历史缓存（注意：缓存存的是精简的 $H_{kv}$ 头！）
k_r, v_r（逻辑对齐）(B, H_q, T_all, d_k)每组重复 $g = H_q / H_{kv}$ 份与 q 对齐，算出 scores: (B, H_q, 1, T_all)

面试必背：KV Cache 字节级显存口算公式

KV 显存账本

$$\text{KV Cache Bytes} = \underbrace{2}_{K\text{ 与 }V} \times L_{\text{layers}} \times H_{kv} \times d_k \times B \times T \times \text{bytes\_per\_elem}$$

系数 $2$
每层既要存 Key 缓存也要存 Value 缓存，缺一不可
$L_{\text{layers}} \times H_{kv} \times d_k$
模型层数 × KV 头数（注意是 $H_{kv}$ 不是 $H_q$！） × 单头维度
$B \times T \times \text{bytes}$
并发 Batch 大小 × 上下文总长度 × 每个元素字节数（FP16/BF16 取 $2\text{B}$，FP8/INT8 取 $1\text{B}$，INT4 取 $0.5\text{B}$）
单位换算口诀：$1\text{ KiB} = 1024\text{ B} = 2^{10}\text{ B}$，$1\text{ MiB} = 2^{20}\text{ B} = 1{,}048{,}576\text{ B}$，$1\text{ GiB} = 2^{30}\text{ B}$。口算时把 $32 = 2^5,\ 128 = 2^7,\ 32768 = 2^{15}$ 全换成 $2$ 的幂次加减指数，3 秒出结果！

直接拿单样本 $B=1$、长文本 $T = 32768\ (2^{15})$、半精度 BF16（$2\text{ Bytes}$）算三笔硬账：

  • Llama-2-7B（MHA：$L=32, H_{kv}=32, d_k=128$）：单词占 $2 \times 32 \times 32 \times 128 \times 2 = 2^{19}\text{ B} = \mathbf{0.5\text{ MiB/token}}$；$32\text{K}$ 上下文共吃掉 $32768 \times 0.5\text{ MiB} = \mathbf{16.0\text{ GiB}}$（加上 $13.5\text{ GiB}$ 权重总计近 $30\text{ GiB}$，你的 RTX 4080 12GB 连零头都装不下！）；
  • Llama-3-8B（GQA：$L=32, H_{kv}=8, d_k=128$）：$H_{kv}$ 砍至 $1/4$，单词降至 $\mathbf{0.125\text{ MiB/token}}$，$32\text{K}$ 缓存立减 4 倍至 $\mathbf{4.0\text{ GiB}}$；
  • Qwen2.5-7B（GQA：$L=28, H_q=28, H_{kv}=4, d_k=128$）：单词仅 $2 \times 28 \times 4 \times 128 \times 2 = 57{,}344\text{ B} = \mathbf{56.0\text{ KiB/token}}$，$32\text{K}$ 缓存仅占 $\mathbf{1.75\text{ GiB}}$！若配 INT4 权重量化（约 $3.8\text{ GiB}$），整套模型 + 32K 长文在你的 12GB 笔记本显卡上轻松起飞！

04代码讲解：MiniMind SwiGLU 与 GQAAttention 源码 + 五大演进总表

模块一：SwiGLU 三线性层无偏置实现

class SwiGLU:
    def __init__(self, cfg, seed=2):
        d, itm = cfg['hidden_size'], cfg['intermediate_size']
        rng = np.random.default_rng(seed)
        self.Wg = rng.standard_normal((d, itm)) * 0.03     # gate 门控投影
        self.Wu = rng.standard_normal((d, itm)) * 0.03     # up 内容投影
        self.Wd = rng.standard_normal((itm, d)) * 0.03     # down 降维投影
    def __call__(self, x):
        silu = lambda z: z / (1 + np.exp(-z))              # SiLU(x) = x·σ(x)
        return (silu(x @ self.Wg) * (x @ self.Wu)) @ self.Wd

ffn = SwiGLU(cfg)
print('SwiGLU FFN:', emb_in.shape, '->', ffn(emb_in).shape)
  1. 三矩阵无偏置布局：Wg 与 Wu 同为 (d, itm)，工业推理框架（如 vLLM）常把这两块矩阵在列维拼成一个 gate_up_proj: (d, 2*itm) 做单次大矩阵乘，算力利用率更高！
  2. 一行前向核心：silu(x @ self.Wg) * (x @ self.Wu) 在高维中间态逐通道门控过滤，再右乘 self.Wd 回到 (B, T, d)。

模块二：GQAAttention、repeat_kv 与增量 KV Cache 闭环

def repeat_kv(x, n_rep):
    """每个 KV 头复制 n_rep 份：[B, kv_h, T, dk] -> [B, kv_h*n_rep, T, dk]。"""
    return np.repeat(x, n_rep, axis=1)

class GQAAttention:
    def __init__(self, cfg, seed=1):
        d, h, kv_h, hd = cfg['hidden_size'], cfg['num_attention_heads'], cfg['num_key_value_heads'], cfg['head_dim']
        rng = np.random.default_rng(seed)
        def w(shape): return rng.standard_normal(shape) * 0.03
        self.Wq = w((d, h * hd)); self.Wk = w((d, kv_h * hd)); self.Wv = w((d, kv_h * hd))
        self.Wo = w((h * hd, d))
        self.h, self.kv_h, self.hd, self.n_rep = h, kv_h, hd, h // kv_h
    def forward(self, x, freqs_cis, mask=None, cache=None, positions=0):
        """x [B, T_cur, d]；cache=(k,v)；positions: 当前 x 的起始位置（预填充=0）。返回 out, (k, v)。"""
        B, T_cur, d = x.shape
        q = x @ self.Wq                       # [B, T_cur, h*hd]
        k = x @ self.Wk                       # [B, T_cur, kv_h*hd]
        v = x @ self.Wv
        def split(t, n_h):
            return t.reshape(B, T_cur, n_h, self.hd).transpose(0, 2, 1, 3)  # [B,n_h,T_cur,hd]
        q, k, v = split(q, self.h), split(k, self.kv_h), split(v, self.kv_h)
        # 只旋转"本步新增"位置的 Q/K（RoPE 后 K 进缓存）
        pos = np.arange(positions, positions + T_cur)
        q = apply_rotary(q, freqs_cis[pos]); k = apply_rotary(k, freqs_cis[pos])
        if cache is not None:                 # 增量：拼接历史 KV
            k = np.concatenate([cache[0], k], axis=2)
            v = np.concatenate([cache[1], v], axis=2)
        k_r, v_r = repeat_kv(k, self.n_rep), repeat_kv(v, self.n_rep)   # [B, h, T_all, hd]
        scores = np.matmul(q, k_r.swapaxes(-1, -2)) / math.sqrt(self.hd)  # [B,h,T_cur,T_all]
        if mask is not None: scores = np.where(mask, -np.inf, scores)
        attn = np.exp(scores - np.max(scores, -1, keepdims=True))
        attn = attn / attn.sum(-1, keepdims=True)                        # [B,h,T_cur,T_all]
        o = np.matmul(attn, v_r)                                         # [B,h,T_cur,hd]
        o = o.transpose(0, 2, 1, 3).reshape(B, T_cur, self.h * self.hd)
        return o @ self.Wo, (k, v)

# ---- 预填充 + 张量形状打印 ----
attn = GQAAttention(cfg)
emb_in = np.random.randn(B, T, cfg['hidden_size'])
o_prefill, (k_cache, v_cache) = attn.forward(emb_in, freqs_cis, positions=0)
print('prefill out:', o_prefill.shape, '| K 缓存:', k_cache.shape, '(B, 2 KV 头, 6 位置, dk=2)')
# ---- 增量解码前向（只算第 6 个新 token） ----
x_new = np.random.randn(B, 1, cfg['hidden_size'])
o_dec, (k_new, v_new) = attn.forward(x_new, freqs_cis, positions=6, cache=(k_cache, v_cache))
print('decode  out:', o_dec.shape, '| K 变长到', k_new.shape[2], '个位置（拼接成功）')
  1. 非对称投影矩阵：Wq 输出维是 h * hd，而 Wk, Wv 输出维只有精简的 kv_h * hd，连线性投影参数量都顺手省掉了！repeat_kv 必须用相邻重复（PyTorch 中为 repeat_interleave 或 unsqueeze(2).expand(...).reshape(...)），让第 0 组的 n_rep 个 Q 头都对准第 0 个 KV 头。
  2. 顺序铁律：先 RoPE 旋转新词、再拼入 KV Cache！因为缓存里的旧 Key 已经带好了各自历史时刻的旋转角，本步只需按绝对起始偏移 positions 旋转当前新增的 q, k，再沿序列轴 axis=2 拼接。
  3. 防坑死穴（第 35 行）：返回值 return o @ self.Wo, (k, v) 存进缓存的必须是 repeat_kv 之前的精简 (k, v)！如果手滑返回了放大后的 (k_r, v_r)，GQA 省显存的收益直接归零！
  4. Prefill → Decode 闭环验证：第 40 行一次性喂入 6 个词建立初始缓存；第 44 行只喂 1 个新词 (B, 1, d) 并传 positions=6，缓存自动增长到 7 个位置且无任何冗余重算。

06小结

本课与 w03 专题收官四句话
  • SwiGLU 门控升维：$\big(\text{SiLU}(xW_{\text{gate}}) \odot (xW_{\text{up}})\big)W_{\text{down}}$ 用 3 个矩阵实现软门控筛选；为对齐 $8d^2$ 参数预算取 $d_{ff} = \frac{8}{3}d$ 并向 256 取整（$4096 \to 11008$）。
  • KV Cache 空间换时间：把 Decode 单步复杂度从 $O(t^2)$ 降为 $O(t)$，但使自回归生成彻底变成受限于 HBM 显存带宽的 Memory-Bound 任务。
  • GQA 省显存黄金公式：$\text{Bytes} = 2 \cdot L \cdot H_{kv} \cdot d_k \cdot B \cdot T \cdot \text{bytes}$；用 $H_{kv} = H_q / g$ 分组共享，把 KV 显存与带宽开销直接砍掉 $g$ 倍。
  • 现代 Decoder-only 五件套已齐：RoPE + Pre-RMSNorm + GQA(KV Cache) + SwiGLU + 无偏置 Linear——至此你已经吃透了从零手写一整座现代大模型的全部底层积木！
30 秒面试表达模板

「现代 LLM 在 FFN 和 Attention 上有两个非常关键的工程权衡：FFN 用 SwiGLU 替代 ReLU，靠 $\text{SiLU}$ 门控与内容支路逐元素相乘增强非线性表达，由于矩阵从 2 个变成 3 个，中间维从 $4d$ 缩到 $\frac{8}{3}d$ 再对齐 256 倍数（比如 7B 的 11008）以维持 $8d^2$ 等参数量。Attention 则用 GQA 解决长文本推理的 KV Cache 瓶颈：按公式 $2 \times L \times H_{kv} \times d_k \times B \times T \times 2\text{B}$，Llama-2-7B 用 MHA 在 32K 长度下单样本 KV 就要 16 GiB，而换成 $H_{kv}=8$ 或 $4$ 的 GQA 后直接降到 4 GiB 甚至 1.75 GiB，同时大幅缓解了 Decode 阶段的显存带宽瓶颈。」

07想检验一下？（可选 · 点击展开）

1. 10 秒现场口算：某 14B 大模型有 $L=40$ 层，$H_q=40,\ H_{kv}=8,\ d_k=128$，用 BF16（2 Bytes）跑并发 $B=4$、上下文 $T=8192$，光 KV Cache 占多少 GiB？

直接套公式（千万别误代 $H_q=40$，要代 $H_{kv}=8$！）：

$$\text{Bytes} = 2 \times 40 \times 8 \times 128 \times 4 \times 8192 \times 2$$

化为 2 的幂次秒算：$8 = 2^3,\ 128 = 2^7,\ 4 = 2^2,\ 8192 = 2^{13}$，连同首尾两个 $2$，合起来是 $40 \times 2^{1+3+7+2+13+1} = 40 \times 2^{27}\text{ B}$。因为 $1\text{ GiB} = 2^{30}\text{ B}$，所以 $\frac{40 \times 2^{27}}{2^{30}} = \frac{40}{8} = \mathbf{5.0\text{ GiB}}$！（若当初用 MHA $H_{kv}=40$，这里就会暴涨 5 倍到 $25.0\text{ GiB}$。）

2. 🎤 面试追问：为什么现代 LLM（LLaMA、PaLM、MiniMind）几乎把所有 nn.Linear 都设成了 bias=False？有哪个著名开源模型是例外？

为什么去掉偏置 bias=False：① 数学冗余与数值稳定性：每个子层前紧挨着无偏置的 Pre-RMSNorm，残差流中的常数偏移对后续注意力/门控贡献极小；PaLM 论文实证表明，去掉所有线性层偏置不仅不掉点，反而提升了百亿级模型在半精度下的训练稳定性；② 算子与通信精简：省去 GEMM 尾声的广播加法与反向跨样本求导归约。

面试加分彩蛋（著名例外：Qwen 系列）：Qwen2 / Qwen2.5 在 FFN 与 o_proj 依然用 bias=False，唯独在注意力的 q_proj / k_proj / v_proj 刻意保留了 bias=True！苏剑林等研究者分析发现，$Q, K$ 上的可学习偏置能为 RoPE 提供静态位置偏置项，显著改善模型在超长上下文外推时的注意力聚焦能力。

3. 🎤 面试深挖（AI Infra 核心考点）：教学代码里 GQA 写了 repeat_kv(k, n_rep) 把 KV 复制了 $g$ 份，在真实的 FlashAttention-2 / vLLM PagedAttention CUDA 内核里，真的会在显存里物理复制吗？

绝对不会在 HBM 显存中物理复制！

如果真在显存里调 repeat_interleave 写出新张量，不仅多占激活显存，更致命的是每次 Decode 依然要从慢速 HBM 搬运 $H_q$ 份数据，GQA 加速推理的带宽优势就彻底归零了！

真实内核做法：在 PyTorch eager 模式下至少用零拷贝视图 k[:, :, None, :, :].expand(B, H_kv, g, T, d_k).reshape(...)（若底层算子支持非连续 stride）；而在 FlashAttention-2 / FlashDecoding / PagedAttention 内核里，直接通过线程块索引整除映射 kv_head_id = q_head_id // n_rep——同一组的 $g$ 个 Query 头共享加载到 GPU 片上高速 SRAM（Shared Memory） 里的同 1 份 $K, V$ 分块，实现真正的「HBM 读 1 次，片上算 $g$ 次」！
