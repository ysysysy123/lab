01痛点与直觉：为什么不能直接套求导公式？

如果模型只有 2 个参数，你可以用纸笔把损失函数 $L(w, b)$ 展开成一大串初等函数再硬求偏导；但当网络堆到 32 层 Transformer（几十亿参数、带分支残差与循环）时，手动展开总表达式会发生指数级项数爆炸。

前向模式 vs 反向模式（对应 AI Tutorial 笔记 §6.5）：若输入参数有 $N$ 个而损失 $L$ 是 1 个标量，前向求导每跑 1 趟只能算出对 1 个参数的导数（共需 $N$ 趟）；反向模式从标量 $L$ 出发往回走，只需 1 趟就能拿齐全部 $N$ 个参数的梯度！这正是 PyTorch loss.backward() 高效的根本原因。

自动微分（Autograd）的破局思路只有一句话：永远不要展开全局公式，把复杂函数拆成加、乘、激活等原子节点，每个节点只管自己门前这一步的局部斜率。

多米诺骨牌 vs 错误账单分摊（取自 01-MLP 笔记导言）

前向传播像推多米诺骨牌：输入 $x$ 与权重 $w$ 一张接一张触发后续节点，算出中间结果 data 并顺手记下「我是谁算出来的」（_prev）。
反向传播像按责任分摊账单：终点算出总误差后，每个节点只接收下游传来的「上游梯度」out.grad，乘上自己的「局部导数」，把责任继续分给自己的输入节点。

02具体数字走一遍：单神经元的 5 步前反向

直接取 concepts/w01_micro_autograd.py 第 98–103 行的真实测试数字：$x = 0.7,\ w = -1.3,\ b = 0.2$，经过线性加权与 $\tanh$ 激活得到输出 $y = \tanh(wx + b)$。点击下方「下一步」（或按键盘 ← →）观察数值与梯度如何在图上流动：

依次执行三次原子运算，生成计算图并缓存前向数值：

$$u = w \cdot x = (-1.3) \times 0.7 = -0.91$$

$$z = u + b = -0.91 + 0.2 = -0.71$$

$$y = \tanh(z) = \tanh(-0.71) \approx -0.610677$$

此时所有节点的 grad 都是初始值 0.0。

调用 y.backward()，第一步先把终点自身的梯度设为 $1$：

$$\frac{\partial y}{\partial y} = 1.0 \quad \Longrightarrow \quad \text{y.grad} = 1.0$$

因为 $\frac{\mathrm{d}}{\mathrm{d}z}\tanh(z) = 1 - \tanh^2(z) = 1 - y^2$（注意直接复用了前向缓存的 $y$！）：

$$\text{z.grad} \mathrel{+}= (1 - (-0.610677)^2) \times \underbrace{1.0}_{\text{y.grad}} = 0.627074$$

对 $z = u + b$，局部导数 $\frac{\partial z}{\partial u} = 1,\ \frac{\partial z}{\partial b} = 1$。加法门就像「梯度路由器」，把上游梯度原封不动发给两个输入：

$$\text{u.grad} \mathrel{+}= 1 \times 0.627074 = 0.627074, \qquad \text{b.grad} \mathrel{+}= 1 \times 0.627074 = 0.627074$$

对 $u = w \cdot x$，局部导数 $\frac{\partial u}{\partial w} = x,\ \frac{\partial u}{\partial x} = w$。乘法门把「对方的前向值」乘上上游梯度：

$$\text{w.grad} \mathrel{+}= x \cdot \text{u.grad} = 0.7 \times 0.627074 = \mathbf{0.438952}$$

$$\text{x.grad} \mathrel{+}= w \cdot \text{u.grad} = (-1.3) \times 0.627074 = \mathbf{-0.815196}$$

含义：$w$ 若微增 $+0.001$，输出 $y$ 会约增大 $+0.000439$。

单步回传通式

$$\text{child.grad} \;\mathrel{+}=\; \underbrace{\frac{\partial\,\text{out}}{\partial\,\text{child}}}_{\text{局部导数}} \;\times\; \underbrace{\text{out.grad}}_{\text{上游梯度 } \partial L / \partial\,\text{out}}$$

加法 $a + b$
局部导数均为 $1$ → 上游梯度原样复制给两侧（残差连接 $F(x)+x$ 能当「梯度高速公路」正是靠它！）
乘法 $a \cdot b$
对 $a$ 的局部导数是 $b$，对 $b$ 的局部导数是 $a$ → 所以前向必须存下输入值（大模型激活显存的大头来源）
激活 $\sigma(z)$
$\tanh'(z) = 1 - y^2$，$\text{ReLU}'(z) = \mathbb{1}[z > 0]$，$\exp'(z) = e^z = \text{out.data}$

03深挖原理：backward() 缺一不可的三条铁律

回看你写过的 Value.backward()，真正控制全局调度的其实只有短短十几行，浓缩成三条铁律。任何一条写错，在简单链式图上可能侥幸蒙混过关，一遇到真实网络就会静默算出错误梯度：

铁律一：终点启动 self.grad = 1.0

反向传播全部是乘法链 $\text{local\_grad} \times \text{out.grad}$。所有节点的 grad 初始化为 0.0；如果不把根节点 self.grad 置为 $1.0$（对应微积分恒等式 $\frac{\partial L}{\partial L} = 1$），整张图回传完永远全为 $0$。

铁律二：多支路汇聚必须用 +=，绝不能用 =

当同一个变量参与多次运算时——比如权重共享、RNN 时间步展开、或者你在 w01_my_autograd.py 测试过的 $y_1 = a \cdot a + a$（当 $a = 3$）——多元微积分全导数公式要求把所有路径传回来的偏导相加：

$$\frac{\mathrm{d}y_1}{\mathrm{d}a} = \underbrace{a}_{\text{乘号左路 } 3} + \underbrace{a}_{\text{乘号右路 } 3} + \underbrace{1}_{\text{加号支路 } 1} = 2a + 1 = 7$$

如果误写成 self.grad = ... 会发生什么？

在 u = a * a 的 _backward 中，第二行 other.grad = self.data * out.grad 会把第一行刚算好的梯度覆盖掉；若再经过外层加法门，最后执行的支路会直接把 a.grad 覆盖成 1.0 或 3.0，彻底丢掉其余支路！（这也解释了为什么 PyTorch 每轮训练必须显式调 optimizer.zero_grad()——因为底层默认一直在做 += 累加！）

铁律三：必须按「DFS 后序反转（逆拓扑序）」依次回传

为什么不能随便按字典或队列顺序调用 _backward()？看下面这个极简 4 节点菱形图（取 $a = 2$）：

$$b = a + 1 = 3, \qquad c = 2b = 6, \qquad L = b + c = 9$$

显然 $L = 3(a + 1)$，因此真实梯度是 $\frac{\partial L}{\partial b} = 3,\ \frac{\partial L}{\partial a} = 3$。观察下方两种回传顺序的差异：

等所有下游支路都到齐后，才轮到 b 发言
  1. L._backward()：先给 b.grad += 1（当前为 1），给 c.grad += 1（当前为 1）。
  2. c._backward()：把 $c=2b$ 的支路传回给 $b$，b.grad += 2 * 1 → 此时 b.grad 完整汇总为 $3.0$！
  3. b._backward()：最后把完整的 b.grad = 3.0 传给 $a$ → a.grad = 3.0（完全正确）。
半截梯度提前出发，上游补发的梯度永远停在半路
  1. L._backward()：b.grad = 1，c.grad = 1。
  2. 过早执行 b._backward()：此时 c 还没回传！b 拿着残缺的 b.grad = 1 传给 a，导致 a.grad = 1.0。
  3. c._backward()：虽然事后把 b.grad 补到了 $3.0$，但 b._backward() 已经执行过且不会重跑，a.grad 永远错停在 $1.0$！
选读：DFS 后序遍历为什么恰好给出拓扑序？

在 build_topo(v) 中，我们先把 v 标记进 visited（防菱形图重复入队），递归访问完所有前驱输入 child in v._prev 后，最后才执行 topo.append(v)。

这意味着：任何一个输入节点一定比依赖它的输出节点更早进入 topo 列表（即 topo 是合法的前向计算序 [a, b, c, L]）。把它 reversed(topo) 倒过来得到 [L, c, b, a]，就严格保证了：轮到任意节点 v 执行 _backward() 时，所有用到了 v 的下游节点必定全都执行完毕了！

04代码讲解：逐段拆解 w01_micro_autograd.py

下面左侧直接截取本仓 concepts/w01_micro_autograd.py 第 18–94 行真实源码；点击右侧任意编号卡片，左侧会自动高亮并定位对应代码行：

class Value:
    """标量计算图节点：记录前向数值 data、反向梯度 grad 以及拓扑父节点"""

    def __init__(self, data: float, _children: tuple[Value, ...] = ()) -> None:
        self.data = float(data)
        self.grad = 0.0
        self._backward = lambda: None
        self._prev = set(_children)

    def __add__(self, other: Value | float) -> Value:
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other))

        def _backward() -> None:
            self.grad += 1.0 * out.grad
            other.grad += 1.0 * out.grad

        out._backward = _backward
        return out

    def __mul__(self, other: Value | float) -> Value:
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other))

        def _backward() -> None:
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad

        out._backward = _backward
        return out

    def __pow__(self, power: float) -> Value:
        out = Value(self.data**power, (self,))

        def _backward() -> None:
            self.grad += (power * (self.data ** (power - 1))) * out.grad

        out._backward = _backward
        return out

    def tanh(self) -> Value:
        t = math.tanh(self.data)
        out = Value(t, (self,))

        def _backward() -> None:
            self.grad += (1.0 - t * t) * out.grad

        out._backward = _backward
        return out

    def __neg__(self) -> Value:
        return self * -1.0

    def __sub__(self, other: Value | float) -> Value:
        return self + (-other)

    def __radd__(self, other: float) -> Value:
        return self + other

    def __rmul__(self, other: float) -> Value:
        return self * other

    def backward(self) -> None:
        topo: list[Value] = []
        visited: set[Value] = set()

        def build_topo(v: Value) -> None:
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)

        build_topo(self)
        self.grad = 1.0
        for node in reversed(topo):
            node._backward()
  1. 节点四件套：data 存前向标量，grad 初始置 0.0，_prev 存直接输入节点集合（建图），叶子节点的 _backward 默认是空函数。
  2. 加法算子与常量包装：第 28 行先把 x + 1.0 里的裸 float 自动提升为 Value；闭包 _backward 用 += 把 out.grad 等额累加给两侧。
  3. 乘法算子：闭包直接捕获前向时的 self、other 与 out，反向时交叉乘对方的前向数值 other.data * out.grad。
  4. tanh 激活与前向值复用：局部导数写成 1.0 - t * t 而不再算一次 $\cosh(z)$，工业级算子（Sigmoid / Softmax / Tanh）都会尽量复用前向输出省算力。
  5. 算子组合复用：减法 a - b 直接拆成 a + (-1.0 * b)，无需额外手写减法反向逻辑；__radd__ / __rmul__ 支持 2.0 * a 左乘常数。
  6. 反向引擎总调度：DFS 后序生成拓扑序 → self.grad = 1.0 点火 → reversed(topo) 逆序逐节点触发局部回传闭包。

06小结

本课浓缩四句话
  • 局部化拆解：反向传播不需要展开全局表达式，每个算子只需实现 $\text{child.grad} \mathrel{+}= \text{local\_grad} \times \text{out.grad}$。
  • 铁律 1（起点）：根节点先设 self.grad = 1.0（$\partial L/\partial L = 1$）。
  • 铁律 2（多分支）：必须用 += 累加各支路偏导（因此训练循环每步前必须 zero_grad()）。
  • 铁律 3（顺序）：必须用 visited 去重的 DFS 后序反转（逆拓扑序），确保下游梯度全到齐后再往上游传。
30 秒面试表达模板

「PyTorch 的 loss.backward() 本质是在动态有向无环计算图上做反向模式自动微分：因为训练损失是标量，反向走一趟就能算出对所有参数的偏导，复杂度与一次前向同阶。手写实现时核心就抓三点：终点梯度置 1、DFS 逆拓扑序保证上游梯度先汇齐、以及用 += 处理变量多路复用——这也决定了工程上每次迭代前必须调 optimizer.zero_grad() 清零历史累积梯度。」

07想检验一下？（可选 · 点击展开）

1. 若计算表达式 $y = a \cdot a + a$（取 $a = 3$），把 __mul__ 和 __add__ 里的 += 全改成 =，a.grad 会变成多少？

设 $u = a \cdot a$，$y = u + a$。逆拓扑序先跑 $y$ 的加法回传：u.grad = 1 且 a.grad = 1；接着跑 $u = a \cdot a$ 的乘法回传：self.grad = 3 * 1 = 3，紧接着同一对象 other.grad = 3 * 1 = 3 再次覆盖。最终 a.grad 会算出错误的 3.0（若拓扑序先跑乘法再跑加法更会被覆盖成 1.0），而正确全导数是 $2a + 1 = \mathbf{7.0}$。

2. 🎤 面试追问：为什么训练 7B 大模型时，参数本身只占 14GB（BF16），前向激活（Activations）却会把显存撑爆？跟今天的 Value.__mul__ 有什么关系？

看第 43–44 行：乘法门 $u = w \cdot x$ 求 $\partial L/\partial w = x \cdot \text{u.grad}$ 时，必须用到前向时的输入激活值 $x$；同理 $\tanh$、Softmax、矩阵乘 `A1.T @ dZ2` 全都依赖前向中间张量。如果不做重计算（Activation Checkpointing），所有层的中间激活都得驻留在显存里等反向传播用完才能释放，序列一长就会占满显存。

3. 🎤 面试追问：做梯度检验为什么推荐中心差分 $\frac{f(w+\epsilon)-f(w-\epsilon)}{2\epsilon}$ 而不是单侧差分 $\frac{f(w+\epsilon)-f(w)}{\epsilon}$？

泰勒展开中，中心差分的偶次项 $f''(w)\epsilon^2/2$ 正负相消，截断误差是 $O(\epsilon^2)$（取 $\epsilon=10^{-6}$ 时截断误差达 $10^{-12}$ 量级）；单侧差分误差只有 $O(\epsilon) \approx 10^{-6}$，在曲率较大的函数处很容易出现假阳性报警。
