01痛点与直觉：计算机浮点数里的「双向上下溢灾难」

在纯数学世界里，$p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$ 与交叉熵 $L = -\log p_y$ 无懈可击；可一旦搬进有限位宽的 GPU 寄存器，指数函数 $e^z$ 的爆炸增长就会在正负两个方向同时埋下致命地雷：

为什么一次 NaN 就能毁掉整轮训练？
IEEE 754 规定任何数与 NaN 加减乘除结果仍是 NaN。只要一个 Batch 里有 1 个样本的某个 logit 触发 inf / inf = NaN，反向矩阵乘 A1.T @ dZ2 就会瞬间把整层权重 W2 染成全 NaN，不可逆转。
  • 灾难一：上溢（Overflow → inf / inf = NaN）：当网络初始化略偏大或学习率稍高时，logit $z$ 很容易冲上几十甚至几百。一旦超出浮点数的最大可表示对数阈值，$e^z$ 直接变成 +inf，紧接着分子除以分母算出 inf / inf = NaN，一轮迭代整网权重全废！
  • 灾难二：下溢（Underflow → inf 或梯度断流）：很多同学以为「算 softmax 前先减最大值 $z_{\max}$ 再算 -np.log(p[y] + 1e-12) 就安全了」（正如过渡代码 w01_mlp_mnist.py 第 58、83 行所写）。错！那只防住了上溢，没防住下溢！当目标类严重猜错、例如 $z = [0, -2, -1000],\ y=2$ 时，$e^{-1000}$ 在 FP64 中会直接下溢为精确的 0.0！不加 $\epsilon$ 会爆 -log(0.0) = inf；就算硬加 1e-12 护栏，损失也会被强行截断在 $-\ln(10^{-12}) \approx \mathbf{27.6310}$，与真实损失 $\mathbf{1000.1269}$ 相差十万八千里，对 $\log(p_y+\epsilon)$ 自动求导更会因为 $p_y=0$ 直接断掉梯度！

第一步防上溢（坐电梯平移）：两个人的身高差，在海拔 0 米量和在珠峰 8848 米量完全一样。把全班最高的那个 logit 当成「0 楼基准」，所有人减掉它，指数输入全都 $\le 0$，输出结果永远关在 $(0, 1]$ 笼子里，绝不撞穿天花板。
第二步防下溢（对数正面拆指数）：既然最终要算的是 $-\log p_y$，根本没必要先算出极小的 $p_y$ 再取对数！直接把 $\log$ 套在分式外层，分子上的 $\log(e^{z_y - m})$ 当场抵消还原成普通减法 $z_y - m$，连 $e^{-100000}$ 都不用算！

02分步公式推导：平移不变性与 Log-Sum-Exp 融合公式

下面顺着上层 04-LLM大模型/教学/07-输出层与损失函数.ipynb 的符号体系，分 4 步推通 PyTorch F.log_softmax 与 nn.CrossEntropyLoss 的底层算子真相：

对任意常数 $c \in \mathbb{R}$，将每个类别的 logit 平移 $z_j \leftarrow z_j - c$，利用指数拆分 $e^{a-c} = e^{-c}e^a$：

$$\frac{e^{z_i - c}}{\sum_{j=1}^K e^{z_j - c}} \;=\; \frac{\cancel{e^{-c}}\, e^{z_i}}{\cancel{e^{-c}} \sum_{j=1}^K e^{z_j}} \;=\; \frac{e^{z_i}}{\sum_{j=1}^K e^{z_j}} \;=\; p_i$$

结论：同一行 logits 整体加减任意常数 $c$，Softmax 输出概率分布分毫不变。

专门挑选当前样本的最大 logit 作为平移基准：$m = \max_{1 \le j \le K} z_j$。此时对任意类别 $j$ 必有 $z_j - m \le 0$，且最大类所在位置恰好满足 $z_{\max} - m = 0$：

$$0 < e^{z_j - m} \le 1, \qquad 1 \;\le\; \sum_{j=1}^K e^{z_j - m} \;\le\; K$$

一石二鸟：① 所有指数项最大不超过 $e^0 = 1$，彻底根除上溢；② 分母求和至少包含一个 $1$，落在 $[1, K]$ 安全区内，取对数绝不会遇到 $\log(0)$！

不要先算除法求 $p_y$，直接对平移后的分式求 $\log p_y$，用 $\log(A/B) = \log A - \log B$ 与 $\log(e^u) = u$ 拆壳：

$$\log p_y \;=\; \log \frac{e^{z_y - m}}{\sum_{j=1}^K e^{z_j - m}} \;=\; (z_y - m) - \log \sum_{j=1}^K e^{z_j - m}$$

取负号即得单样本 nn.CrossEntropyLoss 的工业级融合公式：

$$L \;=\; -\log p_y \;=\; m - z_y + \log \sum_{j=1}^K e^{z_j - m}$$

设三分类单样本 $z = [1000.0,\ 999.0,\ 995.0]$，真实标签 $y = 2$（即 $z_y = 995.0$）：

  • 朴素写法：$e^{1000.0}$ 在 FP64 中直接冲破 $709.78$ 变成 inf，inf / inf = NaN，当场崩溃！
  • Log-Sum-Exp 融合写法：先取 $m = 1000.0$，平移后 $z - m = [0.0,\ -1.0,\ -5.0]$： $$\sum_{j=1}^3 e^{z_j - m} = e^0 + e^{-1} + e^{-5} \approx 1 + 0.36787944 + 0.00673795 = 1.37461739$$ $$L = 1000.0 - 995.0 + \ln(1.37461739) = 5.0 + 0.31817543 = \mathbf{5.31817543}$$ 与 PyTorch F.cross_entropy 计算结果逐位吻合，反向梯度 $\nabla_z L = p - \text{onehot}(y) = [+0.7275,\ +0.2676,\ -0.9951]$ 同样精准无损！
Log-Sum-Exp 交叉熵

$$\operatorname{LSE}(z) = m + \log \sum_{j=1}^K e^{z_j - m}, \qquad L(z, y) = \operatorname{LSE}(z) - z_y = (m - z_y) + \log \sum_{j=1}^K e^{z_j - m}$$

$m = \max_j z_j$
当前样本在类别维（axis=-1, keepdims=True）上的最大 logit 标量
$m - z_y \ge 0$
最大 logit 与正确类别 logit 的直接线性落差（当 $m \gg z_y$ 时主导损失，完全绕开 $e^{z_y - m}$ 下溢！）
$\log \sum_j e^{z_j - m}$
平滑修正项，严格有界于 $[0,\ \ln K]$ 之间，在任何浮点精度下都绝不溢出

对比一下本仓教学过渡代码与大模型课程工业级手搓代码的写法演进：

    @staticmethod
    def softmax(z: np.ndarray) -> np.ndarray:
        # 防数值溢出减去 max
        shift_z = z - np.max(z, axis=1, keepdims=True)
        exp_z = np.exp(shift_z)
        return exp_z / np.sum(exp_z, axis=1, keepdims=True)

    def forward(self, X: np.ndarray) -> tuple[np.ndarray, np.ndarray, np.ndarray, np.ndarray]:
        """
        前向传播:
        X: (B, 784)
        返回: (Z1, A1, Z2, P)
        """
        Z1 = X @ self.W1 + self.b1           # (B, hidden_dim)
        A1 = np.maximum(0, Z1)                # ReLU: (B, hidden_dim)
        Z2 = A1 @ self.W2 + self.b2          # (B, out_dim)
        P = self.softmax(Z2)                 # Softmax 概率分布: (B, out_dim)
        return Z1, A1, Z2, P

    def train_step(self, X: np.ndarray, y: np.ndarray) -> float:
        """
        X: (B, 784)
        y: (B,) 类别索引 0~9
        """
        B = X.shape[0]
        Z1, A1, Z2, P = self.forward(X)

        # 1. 计算交叉熵损失
        log_likelihood = -np.log(P[np.arange(B), y] + 1e-12)
        loss = float(np.mean(log_likelihood))

点评：在 MNIST 温和数值下够用（而且第 102 行手写反向直接用了化简后的 (P - Y) / B 避开了对 log 求导），但如果交给自动微分框架，P[y] 下溢变 0 时第 83 行会立刻卡在 $27.63$ 假死。

# ============ 1. 手搓：log-softmax / 平滑 CE 前向 / 反向 ============

def log_softmax_stable(logits):
    """数值稳定的 log-softmax：先减每行最大值，再取 log 归一化"""
    # logits: (..., V)，在最后一维上做 softmax
    z_max = np.max(logits, axis=-1, keepdims=True)              # 每行最大值，keepdims 保持形状便于广播
    z = logits - z_max                                          # 平移：所有指数项 ≤ exp(0)=1，不会溢出
    log_sum = np.log(np.sum(np.exp(z), axis=-1, keepdims=True)) # log(Σ exp(z)) 即 logsumexp
    return z - log_sum                                          # log_softmax = z - logsumexp

点评：第 9 行直接用减法 z - log_sum 输出 $\log p$，需要概率 $p$ 时再算 probs = np.exp(log_probs)，上下溢双向免疫——这正是 PyTorch F.log_softmax 与 nn.CrossEntropyLoss 的标准等价实现！

03代码讲解：从手写 NumPy 到 PyTorch GPU 五步闭环

理解了底层数学与数值稳定机制后，再看本仓 projects/p1-tiny-llm/src/w01_mlp_mnist.py 第 134–179 行的 run_torch，你会发现每一行 API 都与你手撕过的 NumPy 模块严丝合缝。点击右侧卡片逐段对照：

def run_torch(train_loader, test_loader, epochs: int = 5):
    import torch
    import torch.nn as nn
    import torch.optim as optim

    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    print(f"🚀 PyTorch 训练设备: {device} ({torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU'})")

    model = nn.Sequential(
        nn.Flatten(),
        nn.Linear(784, 128),
        nn.ReLU(),
        nn.Linear(128, 10)
    ).to(device)

    criterion = nn.CrossEntropyLoss()
    optimizer = optim.AdamW(model.parameters(), lr=1e-3)

    for epoch in range(1, epochs + 1):
        model.train()
        total_loss = 0.0
        for x, y in train_loader:
            x, y = x.to(device), y.to(device)
            optimizer.zero_grad()
            out = model(x)
            loss = criterion(out, y)
            loss.backward()
            optimizer.step()
            total_loss += loss.item()

        # 评测
        model.eval()
        correct, total = 0, 0
        with torch.no_grad():
            for x, y in test_loader:
                x, y = x.to(device), y.to(device)
                preds = model(x).argmax(dim=1)
                correct += (preds == y).sum().item()
                total += y.size(0)

        acc = correct / total
        print(f"Epoch {epoch:02d} | Avg Loss: {total_loss / len(train_loader):.4f} | Test Acc: {acc * 100:.2f}%")

    assert acc >= 0.97, f"未达到 97% 准确率目标: {acc*100:.2f}%"
    print(f"🎉 PyTorch 模型达标！最终测试集准确率: {acc * 100:.2f}%")
  1. 算力自适应搬运：自动探测 CUDA GPU（本机识别为 RTX 4080 Laptop GPU）；注意模型权重与每个 Batch 的输入张量 x, y 必须在同一设备上，否则会报经典的 Expected all tensors to be on the same device。
  2. ⚠️ 头号面试红线：最后一层绝不能加 nn.Softmax()！nn.Linear(128, 10) 直接输出未归一化的裸 logits。如果画蛇添足在末尾接上 Softmax，不仅破坏了 Log-Sum-Exp 对数抵消，还会把输入压进 $[0, 1]$，导致 10 分类损失永远降不到 $\ln(e+9)-1 \approx \mathbf{1.4612}$ 以下，且多乘一层饱和导数使收敛慢如蜗牛！
  3. 融合损失 + AdamW 优化器：nn.CrossEntropyLoss() 内部一步打包执行「F.log_softmax（含减 max 防溢出）+ 负对数似然选取 + Batch 取均值」；AdamW 用一阶动量与二阶自适应步长替代手写固定步长 SGD，5 个 Epoch 即可轻松突破 $97.5\%$。
  4. 训练循环五步标准咒语：① zero_grad() 清空上一步残留梯度（呼应第 1 课铁律二：底层默认 += 累加！）→ ② model(x) 前向建图 → ③ criterion(out, y) 算标量损失 → ④ loss.backward() 逆拓扑序反传 → ⑤ optimizer.step() 更新参数。第 162 行务必用 loss.item() 取出纯 Python 浮点数，防止把整轮计算图挂在内存里撑爆显存！
  5. 评测双保险 eval() + no_grad()：model.eval() 负责切换 Dropout 与 BatchNorm 的推理行为（养成工业级肌肉记忆）；with torch.no_grad(): 彻底关闭动态图构建与前向激活缓存，省显存又提速。预测类别直接算 model(x).argmax(dim=1)，因为指数函数单调递增，最大 logit 必然对应最大概率，无需浪费算力求 Softmax！

三端算力混合精度防坑对照（执行训练前必查）

05小结

本课核心四句话
  • 双向陷阱：裸算 $\exp(z)$ 在大数值时触发上溢（FP16 仅 $11.09$、FP32 仅 $88.72$、FP64 仅 $709.78$）导致 inf/inf = NaN；先算 Softmax 再算 $\log p_y$ 则会在负差值过大时触发 $p_y \to 0.0$ 下溢。
  • Log-Sum-Exp 融合公式：利用平移不变性取 $m = \max_j z_j$，并将对数与分子指数正面抵消为 $L = m - z_y + \log \sum_j e^{z_j - m}$，使所有指数输入 $\le 0$、对数输入 $\in [1, K]$，上下溢同时根除。
  • 网络架构红线：搭配 nn.CrossEntropyLoss 时，模型最后一层 nn.Linear 必须直接输出裸 logits，严禁加 nn.Softmax。
  • 工程闭环习惯：训练牢记五步咒语（zero_grad → forward → criterion → backward → step，日志取 .item()），评测必开 model.eval() + with torch.no_grad():。
30 秒面试表达模板

「工程上绝不能把 Softmax 和交叉熵拆成两步写，原因有二：一是上溢，比如在 FP16 下 logit 超过 11.09 算 exp 就会爆 inf 导致 inf/inf = NaN；二是下溢，即使减掉最大值防住了上溢，当正确类 logit 远小于最大类时，先算出 p 会下溢成 0，导致 -log(p) 爆无穷或被 1e-12 截断丢掉梯度。PyTorch 的 nn.CrossEntropyLoss 内部融合了 log_softmax，利用平移不变性提取行最大值 $m$，化简为 $m - z_y + \log\sum e^{z_j - m}$，既让指数项恒在 $(0, 1]$ 内，又让分子对数与指数直接抵消，同时保住了前向精度与 $p - y$ 反向梯度。」

1. 如果新手在 10 分类 MNIST 的 nn.Linear(128, 10) 后面误加了一层 nn.Softmax(dim=-1)，再喂给 nn.CrossEntropyLoss()，训练 Loss 最低能降到多少？

即使模型已经把某样本预测得 100% 确定，第一层 Softmax 的输出顶多是 one-hot 向量 $[1, 0, \dots, 0]$。再把它当成 logits 送进 nn.CrossEntropyLoss 时，内部又做了一次 Softmax，正确类的二次概率只有 $\frac{e^1}{e^1 + 9 e^0} = \frac{e}{e + 9} \approx 0.2320$，对应损失锁死在：

$$L_{\min} = -\ln\frac{e}{e + 9} = \ln(e + 9) - 1 \approx \mathbf{1.46115}$$

正常 MNIST 的交叉熵能轻松降到 $0.08$ 以下，如果你看到训练 Loss 死活卡在 $1.46 \sim 1.50$ 下不去，99% 是因为不小心做了两次 Softmax！

2. 🎤 面试追问：既然训练时减去了 $m = \max_j z_j$，而 $m$ 本身依赖输入 $z$，反向传播求 $\partial L / \partial z_i$ 时，$m$ 的导数会不会改变 $p_i - y_i$ 这个结论？

完全不会改变！因为第一步已经严格证明了恒等式 $\log \sum_j e^{z_j} \equiv m + \log \sum_j e^{z_j - m}$ 对任意实数 $m$ 逐点相等，左右两边定义的是同一个光滑函数。即便显式对右式求偏导（假设最大值在下标 $k^*$ 处唯一取得，即 $\partial m/\partial z_i = \mathbb{1}[i = k^*]$）：

$$\frac{\partial}{\partial z_i}\left(m + \log \sum_j e^{z_j - m}\right) = \mathbb{1}[i=k^*] + \frac{\sum_j e^{z_j - m}(\mathbb{1}[j=i] - \mathbb{1}[j=k^*])}{\sum_j e^{z_j - m}} = \mathbb{1}[i=k^*] + p_i - \mathbb{1}[i=k^*]\underbrace{\sum_j p_j}_{=1} = p_i$$

$\mathbb{1}[i=k^*]$ 项完美正负抵消！因此在 PyTorch 实现中甚至可以直接写 m = z.max(dim=-1, keepdim=True).values.detach() 阻断 $m$ 分支梯度，结果依旧精确等于 $p_i - y_i$。

3. 🎤 面试追问：大语言模型（词表 $V = 128{,}256$，序列长 $T = 8192$）在算最后一层 CrossEntropy 时为什么依然是显存峰值杀手？工业界怎么优化？

虽然 Log-Sum-Exp 解决了数值溢出，但如果先把整个 logits 张量 $(B, T, V)$ 用 FP32 物化在显存里（例如 $B{=}2, T{=}8192, V{=}128256$），仅这一个张量就要占 $2 \times 8192 \times 128256 \times 4\text{B} \approx \mathbf{8.4\text{ GB}}$！工业界（如 FlashAttention 作者的 FusedCrossEntropy 或 Liger-Kernel）会采用 Online Softmax（在线流式更新最大值 $m$ 与指数和）+ 分块融合算子（Chunked Fused CE），边做词表分块矩阵乘边在 SRAM 内完成 Log-Sum-Exp 与反向梯度计算，根本不在显存中落地完整的巨型 logits 矩阵。
